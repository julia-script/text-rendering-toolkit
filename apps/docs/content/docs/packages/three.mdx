---
title: Three.js WebGPU
description: Render LayoutResult values with private or explicitly shared Three.js resources.
---

`@webgpu-text/three` is the optional renderer frontend. It accepts completed layout data and a map
of font handles that can provide outlines.

```ts
import { Text, TextResources } from '@webgpu-text/three'

const resources = new TextResources({ sdfSize: 64, sdfPadding: 0.125 })
const text = new Text({
  layout,
  fonts,
  resources,
  color: 0x55d8ff,
  lit: true,
  outline: { width: 0.6, color: 0xe0f2fe, opacity: 0.9 },
  shadow: {
    offsetX: 0.8,
    offsetY: -0.8,
    softness: 0.6,
    color: 0x020617,
    opacity: 0.7,
  },
})

await text.sync()
scene.add(text)

// Later
scene.remove(text)
text.dispose()
resources.dispose()
```

Omit `resources` for a one-off mesh that owns a private cache and atlas. Inject one owner into
multiple meshes to reuse glyph work and atlas storage; this does not merge their geometry or reduce
draw calls. Dispose every borrower before the shared owner. The application still owns the font
handles and decides when to dispose them. `lit` is fixed when the text object is created; construct
a new object when changing between unlit and lit materials.

Outline width, shadow offset, and shadow softness use layout units. `softness` is a distance-field
falloff rather than Gaussian blur. Ordinary glyphs derive fill, outline, and shadow from one cached
SDF and stable atlas slot, so appearance-only updates do not repeat outline extraction or resource
insertion. Paint plus one antialias texel must fit the safely encodable part of the owner's
`sdfPadding`; the nonlinear eight-bit encoding keeps a small outer reserve so the square SDF cell
never becomes visible. A rejected update leaves the last frame intact. `sdfPadding` is measured in
em units and controls physical reserve, while `sdfSize` independently controls resolution. Public
font handles already expose the required `facts.unitsPerEm`.

COLR v0 layers from `@webgpu-text/font` are expanded only inside renderer resource planning. Their
ordinary outlines share the same monochrome SDF atlas, while palette-zero RGBA and current
foreground remain per-instance appearance. The committed `LayoutResult` stays unchanged. Fonts
without supported layers fall back to the base outline, and caller-supplied `fontKeys` order—not the
renderer—decides when an emoji font is selected. Outline and visual drop shadow currently affect
ordinary glyphs only; COLR layer composition stays unchanged until composed-silhouette semantics are
defined separately.
